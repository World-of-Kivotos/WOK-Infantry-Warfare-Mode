# WOK步战附属-倒地救援

当前版本 `0.1.0-alpha.2`；产物为 `build/libs/wok_downed-0.1.0-alpha.2.jar`，包含已完成专项验收的姿态与拖行同步修复。旧验收记录中的 alpha.1 为当时测试版本，后续交付不再复用旧号。

`wok_downed` 是 WOK步战产品线的独立功能性 MOD。玩家通常遭受致死伤害时不会立刻进入死亡/重生流程，而是转为倒地并等待其他玩家救援。

## 当前功能

- 致死保护：在 `LivingDeathEvent` 阶段取消普通玩家死亡，保留不死图腾的原有优先级。
- 倒地状态：伤员保持 1 点生命，强制卧倒，不能移动、攻击、交互、使用物品、挖掘、乘载具或跨维度。
- 失血倒计时：默认 120 秒；倒计时结束后才执行真实死亡，因此掉落、死亡消息和 `WOK步战核心` 的部署流程仍在最终死亡时触发。
- 队友救援：对倒地玩家按主手右键开始救援，默认需要 8 秒；救援者与伤员必须保持原位和有效距离，任一参与者受击、离线或移动过远都会中断。
- 伤员拖行：潜行并以主手右键点击倒地玩家可开始或停止拖行；伤员保持卧倒并跟随拖拽者身后，拖拽者默认降至 55% 移速且不能冲刺。受击、离线、跨维度、获救或死亡会自动解除拖行。
- 二次伤害：默认有 2 秒保护期，之后新的伤害可以直接终结倒地玩家；可在服务端配置中关闭。
- 医疗软联动：检测到 `wok_trauma` 时会移除流血与大出血；检测到 `wok_body_health` 时通过公开 API 恢复少量部位血量。两个模块都不是必需依赖。
- 管理命令：倒地玩家可使用 `/wokdowned giveup` 放弃救援；管理员可使用 `/wokdowned revive <targets>` 强制救起玩家。
- 战术 HUD：伤员客户端显示倒地状态和失血倒计时，布局兼容窄屏与大屏。

## 依赖与兼容

- 必需：Minecraft 1.20.1、Forge 47。
- 可选：`wok_trauma`、`wok_body_health`、`wok_infantry`。
- MOD 可独立安装，不直接链接或打包任何其他 WOK步战模块的类。
- `moveslikemafuyu` 保持可选：倒地期间锁定客户端与服务端卧倒姿态，拦截其爬行、滑铲、游泳加速和攀爬按键，清除已有爬行/滑铲状态；获救后恢复普通动作。
- `minecraft:generic_kill` 与 `minecraft:out_of_world` 默认位于 `wok_downed:bypasses_downed` 伤害类型标签中，会直接死亡。整合包可通过数据包扩展该标签。

## 服务端配置

首次启动后在世界的 `serverconfig/wok_downed-server.toml` 中生成配置。可调整倒地开关、失血时间、救援时间、距离、移动容差、复苏生命值、部位恢复量、拖行移速/跟随距离、二次伤害保护期及是否允许补枪。

## 构建

从仓库根目录执行：

```powershell
Push-Location wok_downed
..\gradlew.bat clean test build
Pop-Location
```

构建产物位于 `wok_downed/build/libs/`。

## 尚需游戏内验收

当前 alpha 需要在 WOK步战附属专用测试目录中完成双客户端验收：图腾、普通致死、流血致死、部位致死、救援成功/中断、拖行启停/降速/障碍与坡面、补枪、失血死亡、退出重连、窄屏 HUD、大屏 HUD，以及最终死亡后的部署流程。

倒地站姿与 moveslikemafuyu 冲突的专项复现、自动客户端测试及结果见 [姿态兼容验收](docs/DOWNED_POSE_ACCEPTANCE.md)。

拖行时其他玩家看到伤员留在原地的问题，以及带延迟的双客户端回归测试见 [拖行同步验收](docs/DRAG_SYNC_ACCEPTANCE.md)。
