# WOK步战编制配装编辑器

当前编辑器版本 `0.1.0-beta.1`，配套核心 `0.1.0`。交付包内的 `VERSION.json` 和 `SHA256SUMS.txt` 记录准确版本与文件校验值。

解压后双击 **WOK步战编制配装编辑器.html**，用 Edge、Chrome 等现代浏览器打开即可。无需安装、登录或联网。浏览器不会直接修改游戏文件。

界面采用 WOK步战核心 `TacticalBoardTheme` 的战术平板配色、机械外框、灰绿面板及蓝／橙／红／绿操作状态。网页重现的是配置编辑流程，不包含 Minecraft 物品渲染器与游戏内主手读取能力。

## 工作人员怎样交付

1. 向管理员取得游戏刚导出的完整基线数据包，在编辑器点“打开文件”。随包内容标有“演示目录”，只用于熟悉操作，不能视为服务器完整配置。
2. 选择阵营和编制，编辑兵种、槽位、装备、备弹、枪械属性、载具与部署支援。需要新编制时点“＋ 新编制”，以当前编制生成独立副本。
3. 点“保存工程”。把下载的 `wok_editor_project.json` 发给导入负责人或 Codex；它包含当前修改及原始基线，方便继续编辑、核对差异和合并。
4. 如需直接进入游戏，打开“检查与导出”，先解决错误，再点“导出游戏数据包”。工程文件与游戏数据包用途不同，游戏只接受后者。

同一个槽位中的多个装备是供玩家选择的选项；同时发放的装备使用不同槽位。非必需槽不会自动出现“不携带”，使用专门的“添加空装备选项”。一个职业最多 14 个发放位置、每槽最多 64 个装备。备弹按每把枪单独设置，范围 1–4096 发；物品数量为 1–64，实际发放还受物品堆叠能力限制。

配装可以从随包成品库选择，保留其现有配件、状态和备弹，也可输入实际物品 ID 或粘贴游戏导出的完整 SNBT。枪械库 664 项、配件 428 项、载具 246 项，取自本次测试环境，仅作为这个环境的资源参考。更换整合包后，应核对资源是否仍存在。枪型、开火模式、弹匣容量和附件兼容性以实际枪包为准。

## 从游戏导出基线

### 安装配套测试核心

压缩包 `游戏端MOD/` 内附 `wok_infantry-0.1.0.jar`，包含数据包导入导出。文件名与内部版本均为 `0.1.0`；旧 `0.0.1` 同号测试包不再作为当前交付基线，历史包保留供追溯。

1. 退出游戏；专用服务器先停服。备份原 `wok_infantry-*.jar`、`config/wok_infantry/` 和要测试的存档。
2. 把原核心 JAR 移出 `mods`，只保留配套新版核心一个文件。不要同时放两个版本。
3. 放入 `D:\WOK步战测试\1.20.1-Forge_47.4.22\mods`；联机时客户端和服务器使用相同核心 JAR。其余步战附属 MOD 与枪包继续沿用原测试包。
4. 启动并按下面步骤导出基线。若已安装内容相同或更高版本且具备该功能的核心，不需要倒退替换。

要求 Minecraft 1.20.1、Forge 47 系列、Java 17；需要对应枪械／载具内容时保持相关 MOD 和枪包齐全。本次仅将核心放入交付包，未替换你的实际游戏文件。

需要支持阵营配装数据包功能的 WOK步战核心，管理员权限等级至少为 2。在单人游戏或服务器中执行：

```text
/loadoutadmin export "edit_base"
```

文件生成在游戏／服务器运行目录：

```text
config/wok_infantry/catalogs/edit_base.json
```

本项目步战测试环境对应：

```text
D:\WOK步战测试\1.20.1-Forge_47.4.22\config\wok_infantry\catalogs
```

远程服务器需要从服务器目录取得文件。不要把 WOK 本体环境的 JAR 或目录当作步战环境。

## 导入回游戏

把编辑器导出的 `wok_catalog.json` 放进同一 `catalogs` 目录，然后执行：

```text
/loadoutadmin import "wok_catalog.json"
```

游戏会先预览。看完实际返回的说明后，使用游戏给出的确认命令；确认令牌由游戏生成，5 分钟内有效。游戏检查包内容及当前配置未变，并自动备份原配置。使用实际导出文件名替换示例中的名称。

**游戏执行完整目录替换。** 它不是只追加编辑过的那一个编制。多人协作或游戏配置已有新变化时，在工程里点“合并游戏最新配置”，选择从游戏刚导出的完整数据包。工作台按原始基线、本次修改和最新配置合并；同一字段同时修改或删除冲突时不应用合并。把冲突的工程与最新数据包一起交给导入负责人处理。

## 草稿、共享与限制

- 修改自动保存在当前浏览器的本地存储。浏览器禁用存储、清除数据或换电脑时不能依赖它；“保存工程”下载的文件才是可携带交付物。
- 撤销保留当前会话最近 50 次修改。打开另一工程会重建撤销记录。
- 共用同一个全局兵种池的编制，会同时受到该池装备编辑的影响。界面会列出引用方，可点“建立独立副本”后再修改。
- 库里没有的资源可以填写精确 ID，但必须在游戏中验证。网页不能读取 Minecraft 注册表、实时主手物品或试射。
- 装备配件和倍率通过 SNBT 写入；未编辑的标签保留。游戏四项手感控件对应开镜速度、垂直后坐力、水平后坐力和散布；网页另外提供逐枪伤害、穿甲、射速标签的编辑。倍率均为 0.25–15.00，1.00 为默认值。
- 载具页编辑编制中的车型、槽位、生成位置和战损补充时间。车体血量、装甲、运输补给容量不属于 catalog，仍按相应模块配置与项目规则处理。
- 支援列表控制已注册技能能否使用，不创建新技能。队包的实际部署 CD 遵循游戏固定 480 秒规则；其他策略字段是否执行须按游戏当前实现验证。
- 旧测试包内存在失效白名单，不能原样冒充当前完整导入包。随附示例从两套编制构建，明确允许示例中的有效装备，不改动原测试配置。正式工作请使用游戏新导出的完整基线。

## 源码与构建

维护目录为 `tools/loadout-editor/`，无 npm 运行依赖。用 Node 运行 `build.cjs` 生成单文件 HTML；`make-seed.cjs` 只读取指定测试包快照，生成演示配置。资源库是固定快照，编辑器本身不扫描外部目录。

发布说明与测试结果见同目录随附的 `验收说明.md`。
