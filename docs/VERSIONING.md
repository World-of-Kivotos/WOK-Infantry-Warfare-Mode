# WOK步兵战争模式版本规范

本仓库采用“模块独立版本 + 语义化版本”的发布方式。提交代码不等于发布版本，
各模块也不会因为同仓库中另一个模块发布而被动升级。

## 当前版本基线

| 模块 | 当前版本 | 稳定阶段 |
| --- | --- | --- |
| `wok_infantry` | `0.0.1` | 首个开发基线 |
| `wok_infantry_armor` | `0.0.1` | 首个开发基线 |
| `wok_trauma` | `0.0.2` | 修复针剂部位血量持续恢复 |
| `wok_body_health` | `0.0.3-beta.1` | 七部位针剂同步恢复与随机击杀文本测试版 |

## 何时升级版本

- 普通提交、文档、构建脚本、资源整理和未发布功能：不升级版本。
- `PATCH`：已经形成可发布包的向后兼容错误修复，例如 `0.0.1 → 0.0.2`。
- `MINOR`：一批经过验证、向后兼容的新功能里程碑，例如 `0.0.2 → 0.1.0`。
- `MAJOR`：破坏存档、配置、网络协议、物品 ID 或公共 API 兼容性的变更。
- `0.x` 模块在达到稳定标准前保持主版本为 `0`；不得为了单个小功能快速推进次版本。
- 所有模块从 `0.0.1` 开始；没有完成一轮发布验证时，不得仅因提交次数增加版本。

## 发布门槛

只有同时满足以下条件才允许改动 `mod_version`：

1. 本次发布范围已经冻结，不再临时追加功能。
2. `CHANGELOG.md` 已按模块写清新增、修改、修复和兼容性影响。
3. 对应模块构建通过，并检查成品 JAR 中没有硬依赖未安装的其他 WOK 模块。
4. 在指定测试实例中完成启动、核心功能和跨 MOD 联动验证。
5. 配置文件、存档、物品 ID 或网络协议变化已经明确记录。

## 标签和发布名

标签按模块命名，避免不同模块的同版本互相混淆：

- `wok-infantry-v0.0.1`
- `wok-trauma-v0.0.1`
- `wok-body-health-v0.0.1`
- `wok-infantry-armor-v0.0.1`

只有创建正式 GitHub Release 时才创建标签。日常推送不创建标签。
