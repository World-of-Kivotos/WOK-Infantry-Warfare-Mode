# PR 合并链现状与合并方案（2026-10-15 核对）

本文件由 2026-10-15 的一次仓库核对产生，记录 `WOK-Infantry-Warfare-Mode` 当前
9 个开放 PR 的真实依赖关系、已证实无冲突的合并顺序、必须修正的 base，以及
合并后仍未完成的验收项。核对时的远端状态：`main` 停在 2026-08-08 的 `0.0.1` 基线。

## 一、两个关键事实（先前容易误判）

1. **17 个 PR 里只有 1 个已合并。** #5、#6、#8、#9、#10、#11、#13 共 7 个是
   **CLOSED（关闭，未合并）**，不是 merged。它们的内容已经通过分支链包含在
   `codex/体力` 或后续分支里，所以不需要重新打开；但看 PR 列表时不能把
   "CLOSED" 当成"已进 main"。
2. **`main` 没有任何分支保护规则**，合并不会被审批卡住。

## 二、分支拓扑（已用 merge-base 实测）

所有开发分支最终都汇到一条主干 `codex/体力`（PR #4，领先 `main` **229 个提交**）。
在它之上分出**两条互不相交的内容链**（两组文件完全不重叠）：

```
main (0.0.1, 2026-08-08)
  └── codex/体力  PR #4  ... 229 commits  ← 整合主干，尚未进 main
        ├── claude/新版界面 ──> claude/平板外壳 ──> claude/掏平板动画      【界面链】
        │      (#11 CLOSED)      (#12 OPEN)          (#17 OPEN)
        │                                          └── claude/拖行放下  (#16 OPEN)
        └── claude/头盔改模 ──> claude/插板改模 ──> claude/护甲配置        【护甲链】
               (#13 CLOSED)      (#14 OPEN)          (#15 OPEN)
```

- 界面链：`新版界面` 已在 `codex/体力` 里（6 个提交被并进主干），`平板外壳` 领先它 25 个提交，`掏平板动画` 再领先 10 个。
- 护甲链：3 个提交，**只改 `wok_infantry_armor/` 加 3 个文档文件**，与界面链零重叠。
- `claude/拖行放下`（#16）与 `claude/平板外壳`（#12）是兄弟分支（同一个 merge-base
  `826785a8`），不是父子。

## 三、合并顺序（已实测）

界面链与护甲链**彼此独立，内部必须按顺序**。实测 9 个合并步骤全部干净，
唯一的冲突是文档文件的"两边都在顶部新增段落"。

| 顺序 | 动作 | 说明 |
| --- | --- | --- |
| 1 | 合并 PR #4（`codex/体力` → `main`） | 主干入口。229 个提交，含核心 0.5.0-beta.2 与占点 0.1.0-alpha.4 |
| 2 | 合并 PR #12（`平板外壳` → `新版界面`） | 界面链第 1 步 |
| 3 | 合并 PR #16（`拖行放下` → `平板外壳`） | 与 #17 平级，先合哪个都行 |
| 4 | 合并 PR #17（`掏平板动画` → `平板外壳`） | 界面链末端 |
| 5 | PR #14、#15 改为链路内合并 | #14 → #13 的分支，#15 → #14 的分支 |
| 6 | 新建 PR：界面链末端 + 护甲链末端 → `main` | 两条链都已并入主干后的收口 |
| 7 | PR #7、#2、#3 | #7 base 指向已关闭 PR 的分支，见下 |

**#7 必须先把 base 从 `codex/合并头盔改模` 改成 `codex/体力`**：那个 base 分支已经
关闭但已含在主干里，直接合并会把过时快照带回来。

## 四、已实测的冲突与解法

唯一冲突：`CHANGELOG.md`（以及护甲链另加 `README.md`、`docs/VERSIONING.md`）。
三个都是**两边各自在文件顶部新增了不同段落**，不是内容矛盾，解法是**并集**
（两段都保留，各自独立成节）。

需要特别注意的两点：

1. **护甲链的基线很旧，直接合并会造成版本号回退。** `claude/头盔改模` 基于
   2026-09-30 之前的旧点，它带着 `wok_infantry = 0.1.0`、`wok_body_health = 0.0.3-beta.2`、
   `wok_commander_support = 0.1.0-beta.1`、`wok_capture_points = 0.1.0-alpha.2` 等
   旧值。护甲链的 3 个提交**只改自己的 `wok_infantry_armor/gradle.properties`**，
   所以正确做法是把它 rebase 到主干后再合，而不是直接 merge 旧分支。
2. **护甲链的 1.2.0-beta.1（头盔）段落已经通过主干进来了**，只有
   `独立护甲 1.3.0-beta.1` 和 `独立护甲 1.2.0-beta.2` 两节（共 89 行）需要手工补回，
   补回后 CHANGELOG 从 2019 行变为 2108 行。
