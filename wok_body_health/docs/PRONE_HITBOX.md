# 趴姿分段命中

适用于 WOK步战附属-部位血量（modId `wok_body_health`）0.1.0-beta.10 起。

## 解决什么问题

趴下（Tacz-Animation-Additions，下称 TAA，按 C）或在一格缝里原版爬行时，玩家处于陆地上的游泳姿态，移动碰撞箱只有 0.6×0.6 格，而第三人称模型约 1.9 格长。TaCZ 和卓越前线（SBW）的子弹原来就按这个小盒子判定，于是：

- 打脚、头和前伸的手臂会穿模打空；
- 打背上方的空气反而命中；
- 命中部位常与画面对不上。

现在，趴姿玩家被下表中“分段判定”的子弹射击时，改按头、躯干、左右臂、左右腿六段模型判定是否命中和命中部位。移动碰撞箱、姿态、站立玩家和非玩家目标的判定都不变。

| 弹种 | 处理方式 |
| --- | --- |
| TaCZ 子弹（含穿透弹） | 分段判定 |
| SBW 普通弹（手持枪、载具机枪等，`ProjectileEntity`） | 分段判定；`beast` 弹不接管 |
| SBW FastThrowable 系（机炮、火箭等）、即时命中的 ray 武器 | 仍用 0.6 格盒 |
| 原版箭、三叉戟及其他弹射物 | 仍用 0.6 格盒（部位按原来的轨迹交点算） |
| gsl 测距标记弹 | 按模型测距，但不记部位、不补候选 |

## 判定方式

1. **选模式。** 只有在陆地上处于游泳姿态、未骑乘、不在水中、未滑翔的存活玩家才参与：
   - 能读到 TAA 状态：按进入、趴稳、转身、起身四个阶段取模型；
   - 装了 TAA 但读不到状态：一律按趴稳模型；
   - 没有 TAA 状态（例如一格缝原版爬行）：按原版爬行模型。
2. **摆姿势。**
   - 趴稳时按“视线相对身体的水平角 × 俯仰角”查表插值，持 TaCZ 枪与空手各一套；正在爬动时四肢改用划动包络。
   - 趴下、起身过渡用 17 帧关键帧插值，过渡初期站着的上半身仍可被打中；趴着转身按 TAA 的转身公式过渡。
   - 身体朝向读 TAA 的趴姿状态；没有 TAA 状态时按原版规则在服务端模拟观察者看到的身体朝向，不读服务端的 `yBodyRot`（服务端的这个值不会随移动方向转）。
   - 趴下和趴稳时，视线相对身体的水平角与 TAA 客户端一样做低通平滑（τ = 0.1 s，每 tick 最多转 27°）；趴稳和起身时的身体朝向也按 TAA 的低通（τ = 0.06 s）跟随。所以快速转头时，判定会比瞬时视角滞后几 tick（转得越大越久），这与画面一致，不是缺陷。
3. **延迟补偿。** 自行保存每名玩家最近 100 tick（5 秒）的趴姿快照。可回溯的条数：TaCZ 取其 `SAVE_TICK`（默认 20，最多 100），SBW 固定 20。回溯下标、速度修正和平移量逐条照搬 TaCZ、SBW 各自的规则。
4. **逐段求交。** 把子弹射线变换到每一段自己的坐标系，再做与原判定相同的速度扩展、平移和 `AABB.clip`（只认入射面）。各段另按配置外扩，覆盖皮肤外层和装备。
5. **方块遮挡。** 命中点与碰撞箱中心之间隔着方块时丢弃该段，继续看下一段。伸出墙、门、栅栏外的模型部分不能被隔墙打中。
6. **得出部位。** 取最先打中的段：
   - 头段：头部，也是唯一会判为爆头的情况；
   - 躯干：靠颈部的 2/3（模型 12 像素中颈下 8 像素）记胸部，靠髋部的 1/3 记腹部；
   - 左右臂、左右腿：对应同名部位。
7. **一发只算一次。** 同一发子弹已经打中过该目标时直接判打空，穿透弹顺着身体打不会重复结算。
8. **打空时。** TaCZ 让原方法自然返回空结果，taczexpands 的近炸补判照常执行；SBW 返回空，子弹继续飞行，之后打到的方块照常处理。
9. **部位传给伤害结算。** 命中段记入本 tick 的趴姿命中记录（目标、子弹、游戏刻三者都相同才匹配）。TaCZ 枪伤和通用伤害结算先查这份记录，查不到再走原逻辑；独立护甲的护甲部位接口不变。

**粗筛补充。** TaCZ、SBW 用目标当前的 0.6 格盒外扩 1 格挑选候选，过渡期和高延迟回溯时会漏掉伸出的头脚。本模组只在这两个模组的子弹寻敌方法内、对第一次 `Level.getEntities` 查询，补入模型可达范围与搜索范围相交的趴姿玩家。爆炸、测距等其他查询不补，TaCZ 和 SBW 爆炸的受伤名单不变。

## 配置

位于 `config/wok_body_health-common.toml` 的 `[prone_hitbox]` 组。服务器以服务端文件为准。

| 键 | 默认值 | 范围 | 说明 |
| --- | --- | --- | --- |
| `enableSegmentedProneHitbox` | `true` | — | 总开关；关闭后与 0.1.0-beta.9 判定相同 |
| `headMargin` | `0.0625` | 0–0.25 | 头段各方向外扩的格数（帽子层加头盔） |
| `torsoMargin` | `0.03125` | 0–0.25 | 躯干外扩（外套层加背心） |
| `limbMargin` | `0.015625` | 0–0.25 | 四肢外扩（袖子层、裤子层） |
| `transitionLagTicks` | `0` | 0–5 | 过渡动画进度向后推迟的 tick 数，按验收 B4 校准 |
| `vanillaCrawlModel` | `"AUTO"` | `AUTO` / `VANILLA` / `TACZ_TWEAKS` | 原版爬行模型的前后位置。`AUTO`：装了 TaCZ Tweaks 时按 `TACZ_TWEAKS`（整体后移 0.4 格，对应其 `crawl.visualTweak`），否则按 `VANILLA` |
| `sbwLegSegmentsAreLegShots` | `true` | — | SBW 子弹打中腿段时是否按 SBW 的腿部命中处理（腿部减伤和短暂缓慢） |
| `debugLogging` | `false` | — | 逐次把判定写进日志，每秒最多 40 条 |

原来非潜行玩家盒顶统一加 0.0625 格；分段判定不再加这一项，改用上面三个按段外扩的边距。服务器如果给 `minecraft:player` 配置了 TaCZ 的 HeadShotAABB，对趴姿目标不再生效。

## 调试命令

只在装了 TaCZ 或 SBW 时注册，需要权限等级 2。反馈为调试用的纯文本。

- `/wokbodyhealth prone_hitbox show <玩家> [秒数 [回溯tick]]`
  - 秒数 1–120，默认 10；回溯 tick 0–99，不填时画实时快照，填了画历史第 n 条。填回溯 tick 时必须先填秒数。
  - 每 2 tick 用粒子画出各段判定盒的棱，只发给执行命令的人。颜色：头红、胸橙、腹黄、臂蓝、腿绿；白点是碰撞箱中心（遮挡检查的终点）。
- `/wokbodyhealth prone_hitbox log <true|false>`
  - 临时覆盖 `debugLogging`，到服务端停止为止。
  - 日志行以 `[prone]` 开头，字段有：消费方（TACZ/SBW）、目标、射手、回溯下标（`-1` 表示实时）、模式、过渡进度 `t`、yaw、身体朝向或趴稳朝向、趴下/趴稳时平滑后的视线相对身体水平角 `aim`、结果、段、部位、入射点、备注（如 `already_hit`、`occluded=1`）。
- `/wokbodyhealth prone_hitbox stats`
  - 各消费方的命中、打空、不适用、出错次数，以及是否已被自动关闭；
  - 被方块挡掉的段数、`already_hit` 次数；
  - TaCZ 强制打空的请求数与消耗数（两者应相等）；
  - 子弹寻敌作用域内的查询次数与补入的趴姿候选数；
  - 各注入点状态，分段数据表是否已加载，TAA 是否安装、能否读取。

## 兼容性与回退

本模组仍可单独安装。TaCZ、SBW（`superbwarfare`）、TAA（`locknar_doorkick`）都是可选依赖。

| 环境 | 行为 |
| --- | --- |
| 没有 TaCZ 也没有 SBW | 不应用任何 mixin，不注册趴姿相关的事件和命令 |
| 有 TaCZ，没有 SBW | 应用 TaCZ 与 `Level` 两个 mixin |
| 只有 SBW | 应用 SBW 与 `Level` 两个 mixin；没有 TaCZ 时一律按空手模型 |
| 没有 TAA | 趴姿玩家一律按原版爬行模型 |
| TAA 状态读取失败 | 警告一次，按趴稳模型判定，身体朝向用模拟值 |
| 分段数据表缺失或损坏 | TAA 各模式回到原判定；原版爬行模型内置于代码，仍可用 |
| SBW 私有成员反射失败 | 只关闭 SBW 部分 |
| 判定过程出错 | 本发退回原判定；同一消费方累计出错 20 次后关闭到重启，关闭后该模组子弹的粗筛也不再补候选，与 beta.9 一致 |
| TaCZ / SBW 的命中判定（HEAD）注入未生效 | 该模组保持 0.6 格盒，也不补候选；启动时警告 |
| 命中判定注入运行中出错 | 打印一次堆栈后关闭该注入到重启，该模组保持 0.6 格盒，也不补候选 |
| TaCZ 的打空注入未生效 | 打空改为直接返回空结果，判定仍正确，但失去 taczexpands 近炸补判；启动时警告 |
| 粗筛作用域注入未生效 | 不补候选，只用原粗筛；启动时警告 |
| TaCZ 枪械识别出错 | 警告一次，之后一律按空手模型 |
| 快照记录出错 | 第一次出错时打印堆栈；清掉该玩家的快照，下一 tick 重新开始，不中断玩家 tick |
| 调试绘制出错 | 只结束这一个 `show` 会话，第一次出错时打印堆栈 |

- mixin 配置 `wok_body_health.mixins.json` 设为 `required=false`，注入失败只记日志、不会崩溃。所以每次升级 TaCZ 或 SBW 后，都要重做下文验收 A1。
- MixinExtras 由 TaCZ 自带，本模组不打包。
- 紧急关闭：
  - 配置 `enableSegmentedProneHitbox = false`；
  - 或 JVM 参数 `-Dwok.bodyhealth.disableProneMixins=true`，完全不应用趴姿 mixin。
- 与已有注入共存：SBW 对 OBB 载具实体的命中处理、taczexpands 近炸、tacz-tweaks 的逐方块射线、gsl 测距与空爆、SBW 自己往实体查询结果里加 OBB 实体，都照常工作。

已知限制：

- 上表“仍用 0.6 格盒”的弹种不在本次范围内。
- 未单独建模的几何差异：Alex 细臂皮肤（约 0.06 格以内）、minigun 等非默认 TaCZ 第三人称动画、player-animation-lib 叠加的动作、手持 SBW 枪时 TAA 按空手画、切枪动画期间 TAA 画的手持物与服务端不一致。
- 头盔、插板渲染后比皮肤大多少尚未测量，边距默认值待按叠加显示调整。
- `crawl.visualTweak` 是各客户端自己的设置，服务端看不到，`AUTO` 假设整合包设为开启。

## 待用户确认的默认取舍

以下四项按偏向“画面一致、不能隔墙受伤”的原则先定了默认值，需要用户确认：

1. **SBW 打中腿段算腿部命中。** 默认 `sbwLegSegmentsAreLegShots = true`，沿用 SBW 的腿部 0.5 倍伤害和 1 秒缓慢 III。不同意可改为 `false`，腿段只记部位。
2. **gsl 空爆对趴姿目标按模型测距。** 只作用于原粗筛找到的趴姿候选，空爆点会贴近模型而不是 0.6 格盒。要改回需要改代码。
3. **原版爬行静止时用划臂包络。** 客户端手臂停在什么位置服务端无从得知，所以静止时也按整个划臂范围判定，两侧各多出约 0.6 格可被命中的空气。这是偏向射手的取舍，要收紧需要改代码。
4. **伸进方块的模型部分打不中。** 模型伸出墙、门、栅栏另一侧的部分，玩家能看到但打不中，弹孔留在挡板上。这符合“不能隔墙受伤”，代价是“看得到打不着”。要放开需要改代码。

## 游戏内验收清单

**准备**

- 部署到 `D:\WOK步战测试\1.20.1-Forge_47.4.22\mods` 前先征得用户同意。
- 用两台真实客户端（局域网或专用服务端）。盔甲架和僵尸进不了游泳姿态，不能当靶子。
- 射手客户端在 `tacz-client.toml` 的 `[render]` 中开 `HeadShotDebugHitbox = true`，再按 F3+B：显示原 0.6 格盒和原爆头带，作为对照。用 `/wokbodyhealth prone_hitbox show <目标>` 叠出分段判定盒，与模型对照。

**A. 加载**

1. 用 `-Dmixin.debug.export=true -Dmixin.debug.countInjections=true` 启动一次：
   - `debug.log` 有 `Mixing tacz.TaczEntityUtilMixin from wok_body_health.mixins.json into com.tacz.guns.util.EntityUtil`，以及 `Level`、SBW 对应的两行；
   - 有 `Injected tacz.head`、`tacz.wrap`、`tacz.scope`、`sbw.head`、`sbw.scope`、`level`，没有 `Injection MISSING`，没有注入点数不足的报错；
   - 开服时有 `Segmented prone hitboxes active (TaCZ: true, SBW: true).`；
   - 用 javap 看导出的 `.mixin.out/class/com/tacz/guns/util/EntityUtil.class`：`getHitResult` 头部有我们的回调，`AABB.clip` 处变成 WrapOperation 调用，taczexpands 的 RETURN 回调仍在，两个 find* 方法的头部和每个 return 都有作用域回调；
   - 导出的 `Level.class` 中 `getEntities`（`m_6249_`）没有被其他模组 `@Overwrite`。
2. 独立安装矩阵（干净实例）：只装部位血量；部位血量 + TaCZ；部位血量 + SBW；TaCZ + SBW 不装 TAA。都能进入世界，日志无 mixin 报错。
3. 专用服务端跑一次：日志确认 TAA 读取正常；让玩家真的按 C 趴下、起身各一次，TAA 和本模组都没有 `NoClassDefFoundError`。

**B. 命中矩阵**（目标面朝正东趴稳）

1. 射手在正南 8 格，用 TaCZ 步枪，每个点打 5 发：
   - 脚尖、小腿、大腿、臀、腰背、肩、后脑、前额、前伸的手臂都命中，部位记对；
   - 只有头段出现爆头标记和爆头音效；
   - 背上方 0.4 格、身侧 0.35 格的空气打空，并留下弹孔。
2. 射手在正东或正西，顺着身体轴线射击：先打中的是头和手臂，或者脚。
3. 目标视线相对身体转 45°、90°、180°（仰面），俯仰 −25° 和 +10°：部位与画面一致，90° 时右臂在上方。
4. 过渡：
   - 目标按 C 趴下时，射手瞄约 1.2 格高连射，前几 tick 能打中站着的上半身；起身时反过来测；
   - 对照 `log true` 输出的 `t`，用 `transitionLagTicks` 为 0 和 1 各测一轮，选与画面更吻合的一档；
   - 趴着转身 90° 的过程中打手臂，叠加显示与画面吻合；
   - 趴稳后斜向爬行，远端腿的叠加显示不超前画面。
5. 武器：TaCZ 手枪；SBW 手持枪（如 ak_12）；FCP 或 VVP 载具机枪；DragonRise 恐怖分子 NPC（不回溯）；SBW 机炮和火箭与原来一样不受影响；带爆炸伤害的 SBW 弹每次命中只爆一次。
6. 一格缝原版爬行（没有 TAA 状态）：目标侧着看、朝另一方向爬，叠加的身体朝向跟随移动方向，与第三人称模型对齐；停下后转动视角超过 50°，身体被拉动；静止时手臂包络两侧多出的空气请用户确认。
7. 延迟：给射手加 100–200 ms 延迟（可再测 300 ms），目标边爬边挨打，打脚尖。日志回溯下标约等于 ping/50，`stats` 中作用域内补入的趴姿候选数大于 0。
8. taczexpands 近炸弹贴着趴姿目标背上方飞过，仍会触发近炸。
9. 护甲（独立护甲 1.2.0-beta.1）：头段只磨头盔；胸、腹按插板覆盖范围；四肢不耗插板。
10. 方块遮挡：目标分别趴在铁门、栅栏、玻璃板、整格墙后面，以及上半砖或活板门上方，让头或脚伸到另一侧。从另一侧打伸出的部分判打空，弹孔留在挡板上；从同侧打正常命中。
11. 穿透弹：TaCZ 穿透弹（穿透 ≥ 2）从脚往头顺身体轴线打，每发对该目标只结算一次伤害，日志出现 `already_hit`。
12. 爆炸回归：TaCZ、SBW 爆炸弹在趴姿玩家 1–2 格外爆炸，伤害与 beta.9 一致。
13. gsl 空爆与测距：对趴姿目标空爆仍然正常，连续几发不出现“测距穿过目标”。
14. 回归：站立玩家和非玩家目标命中完全不变；`enableSegmentedProneHitbox = false` 时与 beta.9 一致。
15. 性能：两名以上玩家趴着持续交火，用 spark 或 `/forge tps` 查看，`getEntities`、`getHitResult`、`Level.clip` 没有明显的新热点。

**C. 判定标准**

按“部位 × 方向 × 武器”的表格与修复前的基线对照。趴着的人更容易被打中是预期的平衡变化；隔着方块被打中、被同一发子弹打两次，都算缺陷。

## 维护

- 分段数据 `src/main/resources/wok_body_health/prone/taa-1.2.5-segments.json` 由 `tools/prone/k7_segments.js` 从 TAA 1.2.5 的动画数据生成。TAA 升级后重新生成：先从 TAA jar 中解压出 `assets/locknar_doorkick/doorkick_data/prone_tactical_animations.json`（生成器只能读普通文件，不能直接读 jar 内的条目），把环境变量 `TAA_JSON` 指向解压后的文件，`OUT_JSON` 指向上述资源文件，运行 `node k7_segments.js export`。TAA 的原始 JSON 不提交进仓库。
- TaCZ 或 SBW 升级后重做验收 A1，确认注入点仍然存在。
