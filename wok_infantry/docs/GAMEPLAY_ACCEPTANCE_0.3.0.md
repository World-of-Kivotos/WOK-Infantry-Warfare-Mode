# WOK步战玩法调整验收 · 2026-09-10

本轮版本：核心 `0.3.0-beta.1`、部位血量 `0.1.0-beta.1`、倒地救援 `0.1.0-alpha.3`、占点 `0.1.0-alpha.3`。
最终规则以[玩法说明](GAMEPLAY_0.3.0.md)为准：救起各部位及原版生命各 1 点，失明 5 秒；兵力只按彻底死亡和主动重新部署扣除。

## 构建与回归

- 四个模块均完成构建。核心 309 项、倒地 3 项、占点 9 项 JUnit 通过，无失败或跳过。部位血量没有 JUnit 用例，其新增绝对血量 API 由真实客户端场景验证。
- `tools/verify_versions.ps1` 检查源码版本、README、版本表、更新日志、JAR 文件名、内部版本与 modId 一致。
- `tools/verify_mod_independence.ps1` 确认本轮四个模块仅硬依赖 Forge/Minecraft，互相联动保持可选，未引入加载顺序循环。这是依赖元数据检查，不等同于每种组合的实际启动测试。
- 验收 harness 使用单独 source set，生产 JAR 不包含测试类。独立场景实际仅加载核心；联合场景加载核心、部位血量、倒地、占点、TaCZ 1.1.8。

## 真实客户端覆盖

使用 Java 17、Minecraft 1.20.1、Forge 47.4.22，测试均位于 WOK步战专用实例的 `gameplay-acceptance/` 子目录；每次使用新的世界副本。
最终独立场景为 `20260910-standalone-final-02`，35 项检查通过；联合场景为 `20260910-integrated-final-03`。

1. 用实际圈地工具左右键事件选两点，再由正式服务端命令保存基地长方体；不破坏或放置地形。
2. 玩家按正式部署计时进入战场后撤销管理员权限，验证补给按钮没有旧的 60 秒冷却；不足 15 秒不补给，离区重进重新等待完整 15 秒。
3. 消耗配装物品后补至原数量，运输物资对象、归属与生命令牌均保留；服务端倒计时通过网络到达独立提示面板。
4. 倒地不扣兵力、不计入占点。直接调用正式救援完成方法后，验证原版生命 1、七个部位分别为 1、失明 100 tick，且没有旧的抗性 V。
5. 用 TaCZ 原生 crawl 操作切换卧姿。M249 初期卧姿倍率为 0.775，静止后达到 0.1；实际向前爬行失去稳定，起身回到 1。实际派发客户端 GunFireEvent，验证 camera mixin 生效并生成后坐力曲线。
6. 主动重部署扣 1，同一生命损失回调重放不重复扣。全占据点后等待超过十秒，敌方兵力仍为 500。
7. 新生命实际触发玩家死亡事件，最后 1 点被扣至 0，敌方获胜；部署请求被拒绝，部署按钮禁用，死亡后实际复活仍在等待状态且不重复扣点。
8. 管理员统一重置后恢复双方初始兵力、清空据点进度，保留据点定义。

## 边界与已知提示

- 本轮为本机真实客户端与集成服务端验收，未完成完整生产整合包、远程多人或本轮 moveslikemafuyu 组合测试。
- 本轮调用救援完成方法验证血量与效果，没有重复执行双人八秒救援手势、拖行或倒地姿态验收；此前相应修复保留。
- 后坐力检查证明渐进倍率接入真实 TaCZ 开火路径；其主观射击手感仍需玩家实战试射。当前 M249 基础后坐配置保持垂直 8、水平 6，其他枪械配装不变。
- 联合测试沿用本机枪包，日志有已有缺失枪声资源提示；快速测试传送/死亡复活期间会出现 moved-too-quickly 警告，场景服务端位置和状态断言通过，未将这些警告算作已修复。
- 没有替用户圈定实际地图基地。升级后管理员须先设置主基地，再用工具圈定对应补给区。
