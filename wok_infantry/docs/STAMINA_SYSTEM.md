# WOK步战体力系统

体力系统属于 `WOK步战核心`（modId `wok_infantry`），不属于 `WOK` 本体，也不会回灌到 `WOK-本体护甲`。首版使用服务端权威的手部/腿部双池模型，并通过可选反射边界联动 TaCZ 1.1.8+；没有安装 TaCZ 时核心仍能独立启动，腿部体力仍正常工作。

## 资源与行为

| 资源 | 最大值 | 消耗 | 默认消耗速度 | 恢复 |
|---|---:|---|---:|---:|
| 手部体力 | 100 | 主手持 TaCZ 枪械并持续开镜 | 每 tick 0.14（约 2.8/秒） | 停止消耗 3 秒后约 8.4/秒 |
| 腿部体力 | 100 | 实际移动中的疾跑 | 每 tick 0.40（约 8/秒） | 停止消耗 3 秒后约 6.8/秒 |
| 腿部体力 | 同上 | 跳跃 | 每次 10 | 同上 |

腿部降到 0 后，客户端与服务端同时结束疾跑，在原版冲刺入口移除速度加成，持续按冲刺、双击前进或重复发送冲刺请求均不能绕过。默认恢复到 15 才允许再次疾跑；锁定期间尝试冲刺不会继续消耗体力或推迟恢复。创造和旁观玩家不启用体力规则。玩家的两池数值和耗尽锁定写入自身持久化 NBT，并在登录、重生与联机过程中同步给本地客户端。

从核心 `0.2.0` 起，体力网络协议为 `2`，客户端与服务端必须同步更新。旧存档没有锁定标记时可正常读取，零体力仍自动锁定；其他模块无需随之升级版本。

以上消耗、恢复、恢复延迟和疾跑重启阈值都在服务端配置的 `stamina` 分组中，可按整合包节奏调整；客户端不能自行降低消耗。

从 `0.2.1` 起，默认 `recoveryDelayTicks = 60`（20 tick/秒，即 3 秒）。手部和腿部分别计时：再次开镜重新计算手部冷却，再次冲刺或跳跃重新计算腿部冷却；耗尽后被拒绝的冲刺尝试不会重置冷却。整个冷却期间数值不增加。重新登录或重生会重新等待完整冷却，避免运行状态重建后立刻恢复。

现有世界保留其原配置，不会仅因升级 JAR 自动改变 16 tick 的旧值。要采用本次默认值，将该世界 `serverconfig/wok_infantry-server.toml` 的 `[stamina]` 下 `recoveryDelayTicks` 改为 `60`；其他消耗与恢复速度无须改动。

## TaCZ 稳定性联动

手部或腿部体力低于 50（满值 100）后开始产生枪械不稳定；恰好 50 时不晃动，体力越低，晃动幅度越大：

- 手部疲劳是主要来源，归零时达到完整摆动幅度。
- 腿部疲劳最多贡献 35% 摆动，用来表现刚结束冲刺时的呼吸起伏。
- 强度以平滑曲线渐入：手部 40 / 25 / 10 / 0 时，疲劳系数分别约为 10.4% / 50% / 89.6% / 100%，避免跨过阈值时突然抖动。
- 客户端仅在当前帧的相机角度和持枪矩阵上叠加双频呼吸曲线，不改写玩家输入朝向，因此不会积累视角漂移，也不会吞掉玩家自己的鼠标输入。
- 低体力晃动同时接入 Forge 相机角度和 TaCZ 实际使用的手持渲染矩阵，避免客户端 tick 朝向被后续渲染覆盖；腰射/持枪时保留 55% 视觉影响，开镜时使用完整幅度。

TaCZ 的枪械识别与开镜状态通过 1.1.8 API 的反射边界读取。API 缺失或发生不兼容时会记录一次警告并关闭手部/TaCZ 联动，不阻止 `wok_infantry` 加载。

## HUD

从核心 `0.5.0-beta.1` 起，体力条固定在快捷栏正上方、原版经验条那一行（界面预览 `surfaces/16-stamina.js` 的位置 A、外观 A4“战术平板凹槽”，2026-10-05 用户选定）。装不装部位血量位置都一样；以前画在部位血量人形下 `52×11` 伴随槽里的一行和没装部位血量时左下的自绘底板都已删除。

- 外观：一块与小队名单、战况条同款的半透明薄底板（`HUD_PLATE` + 1px `HUD_EDGE` 外轮廓，凹槽和两只耳朵拼成一块），中间两条 3px 凹槽（空段 `HUD_TRACK`，顶行 1px 内阴影），左“手”从左端起填、右“腿”从右端起填，中间 2px 分隔。手槽 50%（开始摆动）、腿槽 15%（力竭后恢复疾跑的门槛，也是一次翻越的消耗）在槽上下两行各点 1px 刻度。两端耳朵放 9×9 手掌 / 靴子剪影（界面图标图集 `hand`、`boot`），外侧 2px 贴边随各自状态变色；布局宽度（GUI 宽 ÷ HUD 倍率）≥ 640 时耳朵里再显示百分比（无阴影，按“100%”预留宽度，数字变短时底板不跳）。
- 位置（GUI 像素，`cx = ⌊屏宽/2⌋`、`h = 屏高`）：凹槽 `[cx−91, cx+91) × [h−30, h−23)`，正好在原版状态行（到 `h−30` 为止）和快捷栏选中框上沿 `h−23` 之间；耳朵 `[h−36, h−23)`，宽 15（有数字时 42）。320×240：凹槽 `[69,201)×[210,217)`；480×270：`[149,331)×[240,247)`，耳朵 `[134,149)`、`[331,346)`；640×360：`[229,411)×[330,337)`，耳朵 `[187,229)`、`[411,453)`；960×540：`[389,571)×[510,517)`。几何由纯函数 `client/hud/StaminaBarLayout` 计算，单测逐档核对。
- 窄屏（GUI 宽约 445 以下，右耳会伸进 TaCZ 弹药读数的禁区 `[w−117, w−5) × [h−48, h−22)`）：凹槽右端最多到 `w−119`，靴子挪进原版两组状态图标之间永远空着的中缝，做成 `[cx−6, cx+6) × [h−40, h−30)` 的小凸台；左耳缩成 10×11（`[cx−101, cx−91) × [h−36, h−25)`，夹在部位血量人形和快捷栏列之间），贴边缩成 1px，腿的贴边画在凹槽右端 2px。只按屏宽判定，切武器时不会跳。
- GUI 缩放 1 且启用 `ui.minimumScale2x`（核心 HUD 2×）：凹槽仍按 1× 贴着 1× 的原版快捷栏，两只耳朵按 2× 画（`[h−49, h−23)`，剪影 18×18）；960×720 窗口的布局宽度是 480，不显示数字。2× 耳朵会伸到聊天最后一行（`h−40`）之上，窗口窄到左耳会碰到聊天背景时（默认聊天宽度下窗口不足约 906 像素，例如 854×480）耳朵保持 1×。
- 状态：常态灰绿 `NEUTRAL_B`（剪影、数字 `LIGHT_MUTED`）；低于 50 橙 `ACCENT_B`；15 及以下红 `DANGER_B`，贴边、剪影和数字 2Hz 闪（填充本身不闪）。刚消耗掉的一段留 0.6 秒残影（填充色 40% 不透明，取最近 0.6 秒内收到的最高值），恢复中（最近 0.4 秒内上升过）条头亮 1px。腿耗尽锁疾跑期间腿槽空段换成暗红（`DANGER` 与 `FRAME` 各半，读作红色空槽而不是满条）、内阴影更暗、刻度变亮，靴子换成红锁，贴边和数字红；回到 15 解锁时靴子换成绿勾、贴边变绿 1 秒。骑马、驴、骆驼等可跳坐骑时腿槽改显示跳跃蓄力（浅色、向上箭头，百分比为蓄力；骆驼冲刺冷却中整组变灰），手槽照常；乘坐其他载具（船、矿车、卓越前线载具等）时腿槽、靴子、数字变灰（坐着不消耗腿）。腿槽刻度按默认门槛 15 画；服务端改了 `legExhaustedResumeThreshold` 时刻度不跟着变（体力协议不变）。
- 原版让位：体力条显示时（生存/冒险模式、服务端启用体力、活着、未按 F1、客户端配置 `hud.staminaBar` 开）在 `RenderGuiOverlayEvent.Pre` 里取消原版 `EXPERIENCE_BAR`（经验条和等级数字）与 `JUMP_BAR`（骑马跳跃条）。监听用最高优先级，先于其他 MOD 的监听取消，不会留下没配对的 Post；这两个覆盖层都不改 Forge 的 `leftHeight`/`rightHeight`，红心、护甲、饱食度、氧气、坐骑血量、物品名、动作栏、聊天和其他 MOD 往状态栈加的行都不动。创造、旁观、死亡或服务端关闭体力时不画体力，原版经验条照常；`hud.staminaBar = false` 时始终显示原版经验条和跳跃条、不显示体力（腿耗尽照样锁疾跑）。
- 部位血量：核心不再往 `BodyHealthHudApi.companionSlot` 里画，那条伴随槽空着，部位血量这一轮不用发版，新旧核心与新旧部位血量都能各自独立安装；核心仍调用它来定位人形，让小队名单停在人形上方。`ClientStaminaState.snapshot().enabled()` 的签名与语义不变。部位血量以后可反射调用 `InfantryHudApi.usesBodyHealthCompanionSlot()`（返回 `false`）决定不再预留这条槽；方法不存在时（旧核心仍画在那里）应照旧预留。
- 卓越前线 0.8.9 自带一条体力线（`StaminaOverlay`，客户端配置 `superbwarfare-client.toml` 的 `stamina_hud`，默认开）：反汇编核实它在它自己的体力动作进行时画在 `[cx−90, cx+90) × [h−24, h−23)`，正好压在本体力条凹槽的底边外轮廓那一行。核心不去取消别的 MOD 的覆盖层，整合包应把 `stamina_hud` 设为 `false`（步战测试端已于 2026-10-05 20:38 改为 `false`，原文件备份为同目录的 `superbwarfare-client.toml.backup-20261005-203838-before-stamina-hud-off.bak`）。
- 管理员需要精确值时可用 `/battle admin stamina status`。

权限等级 2 的服主可用 `/battle admin stamina status` 查看自身当前数值，用 `/battle admin stamina set <手部0-100> <腿部0-100>` 复现疲劳状态，或用 `/battle admin stamina reset` 恢复双池。该入口用于验收和调参，普通玩家无权调用。

## 游戏验收重点

当前冷却实测见 [0.2.1 恢复冷却验收](STAMINA_ACCEPTANCE_0.2.1.md)，前版冲刺和晃动实测与复验命令见 [0.2.0 体力验收记录](STAMINA_ACCEPTANCE_0.2.0.md)。

1. 320×240、960×720（GUI 1，2× HUD）和 640×336 分别检查快捷栏上方的体力条：凹槽在原版经验条那一行、两端耳朵不压快捷栏、副手格、红心/护甲/饱食度行、部位血量人形与总数小牌和 TaCZ 弹药读数；原版经验条和等级数字不再出现，骑马时原版跳跃条换成腿槽蓄力；切到创造模式后原版经验条回来。
2. 连续疾跑约 12.5 秒应耗尽腿部体力；归零后不能靠反复按键保持疾跑。
3. 连续跳跃应每次扣除 10 点腿部体力，落地和坠落不应被误记为跳跃。
4. 持 TaCZ 枪开镜约 35 秒应耗尽手部体力；非 TaCZ 物品不消耗手部体力。
5. 50 以下摆动应平滑淡入，在 40、25、10、0 时逐渐增强；松开开镜后视角不应残留偏移。刚跑停、腿部归零但手部充足时只应出现较轻呼吸摆动。
6. 双人联机确认 HUD 数值来自服务端、重新登录仍保留当前体力、创造/旁观模式不显示体力 HUD。
