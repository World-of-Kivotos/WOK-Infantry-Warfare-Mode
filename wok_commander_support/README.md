# WOK步战附属-指挥官支援

当前产物 `build/libs/wok_commander_support-0.1.0-beta.3.jar`，最低核心版本为 `0.3.0-beta.6`（依赖核心本版新增的受理回调 `SupportProvider.accepted`；失败分级、冷却返还、`requiresLoadedFootprint` 与照射许可内圈接口来自核心 0.3.0-beta.5）。开发构建自动读取核心 `gradle.properties`，不再固定使用旧同名包。

Minecraft 1.20.1 / Forge 47.4.22 独立附属模块，modId 为
`wok_commander_support`，当前版本 `0.1.0-beta.3`。本模块强制依赖
`WOK步战核心`（`wok_infantry`），但不依赖创伤治疗、部位血量、独立护甲、
TaCZ 或任何具体载具 MOD。Create Big Cannons 只作为空袭弹体的可选软依赖，
卓越前线只作为爆炸实现的可选软依赖；缺失时模块和侦察卫星仍可启动，
CBC 缺失会令两种空袭条目明确显示不可用。卓越前线缺失时 F-15EX 安全回退
CBC HE 爆炸，必须使用火炮指示器的 F-16C 宝石路支援则显示不可用。
三种榴弹炮击要求卓越前线、不需要 CBC，缺卓越前线时显示不可用；无人机侦察两者都不需要
（它的引擎声和击落声包装的是卓越前线的声音，未安装时静音）。所有第三方内容只按注册 ID、
反射字符串或 tag 软联动，成品里的类不引用任何第三方类，也不打包第三方声音、贴图或模型。

## 侦察卫星

- 仅当前阵营指挥官能在战术地图的“支援”页呼叫。
- 点选一个扫描中心；服务端校验其所在维度、坐标范围和半径 150 格扫描区的世界边界，不要求扫描区内的区块已经加载（定义声明 `requiresLoadedFootprint=false`），也不会为扫描加载区块。扫描只读取已加载的实体，未加载区域里没有可报告的目标。
- 冷却 10 分钟（以《步战模式公示表》阵营表为准），按阵营和技能 ID `wok_commander_support:recon_satellite` 持久化；更换指挥官或重启服务器不会刷新冷却。
- 呼叫后立即扫描，此后每 5 秒刷新一次，共覆盖 30 秒（6 个刷新窗口）。
- 情报属于阵营：指挥官在侦察期间阵亡（包括停在死亡界面）、进入等待区或换维度，扫描照常刷新到结束。首次扫描就失败（什么都没发布到地图上）时返还冷却；首次扫描之后指挥官下线，本次侦察提前结束，冷却不返还（核心只接受呼叫者当前在线的会话发布情报，重生前的旧实体也不算）；指挥官离开受理阵营时跳过该次扫描，由核心在下一步前取消任务。
- 扫描同维度、圆形水平范围内已部署且存活的敌方玩家；玩家正在乘坐实体时只显示所乘载具的接触点，避免两个红点重叠。
- 同时扫描带有 WOK 编制 ownership 的敌方载具，包括当前无人乘坐的已部署载具。
- 结果仅出现在调用方阵营的战术地图中，统一显示为不可手动选择/删除的红点；目标离开区域后，旧点会在一个刷新间隔后自然消失。
- 红点是运行期临时情报，不占玩家手工标记额度、不写世界存档，服务器重启后不会残留。

## 无人机侦察

一架侦察无人机在目标上空盘旋约 2 分钟，每 10 秒把扫描到的敌人刷到己方战术地图上，然后飞离。它是看得见、打得下来的实体：被击落时任务提前结束。

| 项目 | 数值 |
| --- | --- |
| 技能 ID / 短名 | `wok_commander_support:recon_drone` / 无人机侦察 |
| 目标模式 | 点目标 |
| 冷却 | 6000 tick（5 分钟，公示表） |
| 在途时间 | 0（受理后立即起飞） |
| 任务长度 | 60 步 × 40 tick，约 2 分钟 |
| 扫描 | 第 0、5、10……55 步，每 10 秒一次，共 12 次；中心固定为目标点，半径 96 格 |
| 红点保留时间 | 240 tick（12 秒），比扫描间隔长，红点不会在两次扫描之间闪掉 |
| 盘旋 | 圆心为目标点，半径 24 格，速度约 0.6 格/tick，盘旋时压坡度 22° |
| 飞行高度 | 取“目标地表 + 64”与“盘旋圈上 16 个采样点的最高地表 + 40”中较大的一个，不超过世界建筑上限 − 16；只读已加载区块的高度 |
| 血量 | 200 |
| 区块要求 | 扫描区不要求已加载（`requiresLoadedFootprint=false`）；起飞前要求盘旋区已加载，见下 |

### 时序

1. 受理即执行第 0 步：先确认有在线指挥官和战局服务，再检查盘旋圈外扩 2 格所覆盖的区块（最多 5×5 个）全部已经加载完成、并处于实体 tick 状态。检查只用 `getChunkNow`，不会为无人机加载区块。不满足就不起飞，返还冷却，原因为“目标上空盘旋区域未加载，需有友军靠近目标”。
2. 在目标上空生成无人机（实体 UUID 等于任务 callId，记录受理阵营），随后立即扫描一次并发布到己方地图。
3. 第 1 至 59 步：每步确认无人机还在；第 5、10……55 步扫描。
4. 第 59 步（受理后约 118 秒）不再扫描，无人机改平、加速爬升离场，约 5 秒后自行消失。第 55 步（约 110 秒）那次扫描的红点保留到约 122 秒。

无人机的位置由同步给客户端的盘旋参数和游戏时间推算，服务端和客户端算出同一条航迹，所以飞行平滑，不靠位置包插值。

### 扫描内容

复用侦察卫星的扫描器：同维度、半径 96 格内已部署且存活的敌方玩家（乘坐载具时只显示载具），以及带 WOK 编制 ownership 的敌方载具；只读已加载的实体。情报规则与侦察卫星相同：属于受理阵营；指挥官阵亡、进入等待区或换维度时照常刷新；指挥官下线时本次结束、不返还；指挥官离开受理阵营时跳过该次扫描，由核心在下一步前取消任务。

无人机自己不会出现在任何一方的战术地图上：扫描只报告玩家和 WOK 编制载具，敌方只能在天上看到它、听到它。

### 击落

- 只有两类伤害会扣血：爆炸类（伤害类型属于 `#minecraft:is_explosion`，卓越前线的导弹、炮弹等爆炸也在其中）和卓越前线的弹体直击 `superbwarfare:projectile_hit`（导弹、防空炮弹直接命中）。子弹、近战、箭、摔落等一律不扣血。
- 与无人机同阵营的玩家造成的伤害被忽略，包括玩家驾驶载具开火；阵营用核心的战局服务查询。
- 血量归零即被击落：空中爆炸（粒子和击落声），随后带着前冲惯性受重力坠落、机尾冒烟，最多 100 tick；落地或超时再爆一次后消失。坠毁过程中不再受伤，不破坏方块、不伤害实体、不掉落物品。下一步任务结束，聊天提示原因“侦察无人机已被击落”，冷却不返还。
- 卓越前线分不清 WOK 阵营：己方的防空武器也能锁定己方无人机，但造成的伤害会被忽略；卓越前线近防炮、激光塔的自动模式不会主动攻击它。
- vvp 兼容：本模块带数据包 tag `data/vvp/tags/entity_types/pantsir_air_target.json`（`replace: false`，只加 `wok_commander_support:recon_drone`），让 vvp 的铠甲（Pantsir）防空系统把它当作空中目标。未安装 vvp 时这个 tag 不起作用。

### 信号丢失与自我清理

- 某一步找不到无人机、无人机已被移除，或它所在区块不再处于实体 tick 状态（例如目标附近的玩家都离开了），任务结束，原因“侦察无人机信号丢失”，冷却不返还。服务端发现无人机下一位置不在实体 tick 区块时会直接移除它，避免服务端停在原地而客户端继续沿航迹飞。
- 实体类型声明 `noSave`，无人机永远不会写进区块存档。
- 起飞时写入到期时间（起飞 + 59 × 40 + 100 tick，约 123 秒），到期自毁，用来兜底战局重置或服务器异常。
- 到期自毁不只靠无人机自己的 tick：区块仍加载、但已落在模拟距离（`simulation-distance`）之外的无人机，或所在维度没有玩家而停止实体 tick 时，服务端不会再 tick 它。为此本模块另有服务端兜底巡检 `ReconDroneWatchdog`（`@Mod.EventBusSubscriber` 自注册，每个服务端 tick 结束时运行，只弱引用、不写存档，开服前和停服后清空）：已起飞的无人机过了到期时间（坠落中的残骸除外，它自己会在 100 tick 内结束），或连续超过 20 tick 没被服务端 tick，就直接移除。这样战局重置（核心清空任务表、不回调附属）、任务在附属之外异常结束、正常完成后的离场途中或坠落途中失去 tick 时，无人机都不会悬停在空中、碰撞箱留在原处。任务还在执行时被巡检移除的无人机，下一步按“信号丢失”结束。
- 不是由任务起飞的无人机（例如用 `/summon` 召唤的）在第一个 tick 就自行消失；所在区块不 tick 时由巡检在下一个服务端 tick 移除。
- 任务失败抛出前，以及核心在起飞后取消任务（`abandon`）时，按 callId 找到无人机并移除；已经在坠毁的残骸除外，让它播完坠毁过程再消失。

### 外观与声音

- 模型是本模块用原版 `EntityModel` 手写的通用固定翼长航时侦察无人机，整体轮廓参考 MQ-1、TB2 一类机型但自行设计：细长机身、卫星通信鼓包、机头下方光电球、平直主翼（翼展 12 格，机长约 6.4 格）、倒 V 尾加腹鳍、机尾推进式螺旋桨（会转）。左红右绿翼尖航灯常亮，尾部白色频闪与腹部红色信标交替闪烁，击落后熄灭。盘旋时整机按压坡度倾斜。
- 可见距离：客户端渲染距离设为 320 格（`shouldRenderAtSqrDistance`，不做视锥剔除），但这只是渲染上限，实际看得到多远由服务端是否把实体同步给该玩家决定。实体追踪距离为 16 区块（256 格，再乘服务器 `entity-broadcast-range-percentage`），且不超过服务器视距 × 16 格，都按水平距离计算。默认视距 10 时约 160 格水平距离以内可见，视距 16 及以上时最远约 256 格；单人与局域网以房主的渲染距离为视距。超出这个范围的玩家收不到实体，既看不到无人机，也听不到引擎声。
- 贴图 `assets/wok_commander_support/textures/entity/recon_drone.png`（256×64，灰色系，分面板线、舵面、镜头、航灯等区域）由本模块自行生成，不来自任何第三方 MOD。没有新增 GeckoLib 依赖。
- 引擎声 `recon_drone_engine`（包装 `superbwarfare:ju_87_engine`）由客户端绑定无人机循环播放，音调 1.5；客户端自行做线性衰减，可听距离 = 无人机离地高度 + 64 格（离地高度按目标地表算）；击落后 1 秒内降调淡出。
- 击落声 `recon_drone_destroyed`（包装 `superbwarfare:explosion_air`，sounds.json 音量 16，客户端约 256 格可听，服务端广播 256 格），空中爆炸和落地时各一次。
- 两个声音都依赖卓越前线的原声，未安装卓越前线时静音，无人机照常工作。字幕为“侦察无人机引擎嗡鸣”“侦察无人机爆炸”。

### 地图表现与编制

- 战术地图按情报类支援（`INTELLIGENCE`）显示。
- 新生成的默认编制中，学院军“千禧年研讨会机动部队”和“研讨会骑兵军团”开放无人机侦察（由核心 0.3.0-beta.6 的默认白名单提供）；其他编制见下文“编制权限”。

## 榴弹炮击：三种共用的规则

三连发榴弹炮击、快速三连发105毫米榴弹炮打击、五连发105毫米榴弹炮打击共用同一套实现，只是参数不同（各自一节，见下）。

- 可用性：要求已安装卓越前线 `0.8.9+`，并且它的 `CustomExplosion` 接口能通过反射解析；不需要 Create Big Cannons。缺卓越前线时显示不可用（“需要安装卓越前线”），接口解析失败时显示“卓越前线 CustomExplosion 接口不可用”。
- 不生成炮弹实体。每发在落点直接调用卓越前线 `CustomExplosion`（与 F-15EX、F-16C 共用同一个反射桥），直接来源是一个移到落点、但不加入世界的原版 marker，攻击者是呼叫的指挥官。是否破坏方块跟随卓越前线服务端的 `EXPLOSION_DESTROY` 配置，与 JDAM、F-16C 一致。
- 区块要求：定义声明 `requiresLoadedFootprint=true`，受理和每一步执行前都要求危险区内的区块已经加载；执行期间区块卸载按核心取消处理。

### 时序

记受理时刻为 A（单位 tick）：

- 第 w 波（从 0 数）的炮声在 A + w × 波间隔 响起，这一波有几发就响几声，相邻两声相隔 6 tick（155 级）或 3 tick（105 级）。第 0 波的第一声在受理那一刻响。
- 每波第一发在它的第一声炮声之后“预备时间”落地，同一波的各发相隔 0.5 秒（10 tick）落地。
- 每发落地前 1.5 秒（30 tick），在落点地表上空 20 格开始播放来袭呼啸。
- 核心层面：在途时间 = 预备时间 − 30 tick，任务每步 10 tick，第 k 步在 A + 在途时间 + 10k 执行。第 w 波第 r 发（都从 0 数）在第 3 + w × 波间隔 / 10 + r 步落地，在它前 3 步开始呼啸；任务在最后一发落地那一步结束，所以步数 = 最后着弹步 + 1。
- 受理时（核心的 `accepted` 回调）：立刻响第 0 波的第一声，并把其余所有炮声一次排进延迟炮声调度器。调度器由服务端 tick 驱动、按 callId 分组、不写存档，开服前和停服后清空；单个炮声出错只记日志并丢弃这次呼叫剩下的炮声，不影响任务。
- 第 0 步：检查目标点仍在世界边界内、卓越前线爆炸接口和粒子档可用、marker 能创建，然后开始第一发的呼啸。第 0 步不落弹。落点计划由 callId 确定，每一步按 callId 重新算出，provider 不保存每次任务的状态。
- 任务提前结束、正常完成，或第 0 步之后被核心取消（`abandon`）时，剩余炮声一并取消。第 0 步之前核心取消任务（会返还冷却）时附属收不到通知：在途期内本该响的炮声照常响，之后的炮声在租约到期（过了预期的第 0 步时刻 20 tick）时丢弃。

### 炮声与呼啸

- 炮声来自一个虚拟炮阵地：从目标中心朝指挥官受理时所在位置的水平方向偏移 180 格（155 级）或 120 格（105 级），高度为目标处的地表 + 40。目标所在列未加载时改用指挥官的高度 + 40，再不行用海平面 + 40；不读未加载区块。指挥官站在目标点 1 格以内时，方向由 callId 固定生成。
- 炮声敌我都能听到（声音类别 `HOSTILE`）。可听距离要覆盖“炮阵地偏移 + 危险区半径 + 64 格”，即危险区远端再往外 64 格：
  - 155 级 `howitzer_155_report` 包装 `superbwarfare:plz_05_veryfar`，sounds.json 音量 20，客户端约 320 格可听，要求约 305 格（含炮阵地高出的 40 格斜距）；
  - 105 级 `howitzer_105_report` 包装 `superbwarfare:mk_42_veryfar`，音量 14，客户端约 224 格可听，要求约 214 格；
  - 两者的服务端广播半径都是 384 格。这些数值由契约测试 `SoundAssetContractTest`、`ArtilleryAudibilityContractTest` 锁定。
- 来袭呼啸：装了 CBC 时用 `artillery_incoming_cbc`（包装 `createbigcannons:shell_flying`），否则用 `artillery_incoming_sbw`（包装 `superbwarfare:shell_fly`）；音量 0.7，音调 155 级 0.95、105 级 1.15；服务端广播 128 格，覆盖危险区及其周边。
- 字幕：“远处155毫米榴弹炮开火”“远处105毫米榴弹炮开火”“炮弹来袭呼啸”。声音只按注册 ID 引用卓越前线和 CBC 的原声，没有打包任何音频；未安装对应 MOD 时静音。

### 散布与落点

- 每一波先在以目标为圆心、半径 R_area 的圆内均匀取一个瞄准点（距离 r = R_area × √u，u 为 0 到 1 的均匀随机数）。
- 每一发在瞄准点上再加一个二维高斯偏移（每个轴的标准差为 σ）；偏移超过 scatterMax 就重抽，不是拉回到边界上（最多重抽 64 次，用尽时落在瞄准点；按现有参数单次被拒的概率约 3.7%，实际碰不到）。所以所有落点到目标的水平距离都不超过 R_area + scatterMax。
- 随机数可复现：每次抽取用独立的 `SplittableRandom`，种子由 callId 的高低两半、波序和发序经 SplitMix64 混合得到。
- 落点高度 = 该列 `MOTION_BLOCKING_NO_LEAVES` 地表（第一个空格）+ 0.25 格，并限制在世界建筑高度内；只读已加载区块。
- 单发落点超出世界边界、或所在列没有加载时，跳过这一发并记日志，任务继续。

### 地图表现与编制

- 战术地图按攻击类支援（`OFFENSIVE`）显示，红色危险区半径 = R_area + scatterMax + 爆炸半径。
- 三种炮击都不在任何新生成的默认白名单里：《步战模式公示表》中拥有它们的编制在代码里还没有，需要由管理员加进对应编制的白名单（见下文“编制权限”）。

## 失败处理

规则是“打不出去就返还冷却、立刻能再呼叫”，不另加防刷限制。冷却在受理时扣下；只有在第 0 步还没完成时结束的任务才会返还，第 0 步执行过之后一律不返还。各技能的第 0 步是：侦察卫星的首次扫描、无人机的起飞和首次扫描、空袭的释放、炮击的预检（炮击第 0 步只做预检和第一发的呼啸，不落弹；第 0 步完成之后哪怕还没落弹，取消也不返还）。返还由核心按比对写回：管理员中途清除或改过冷却，就保持管理员的结果。任务没有完成就结束时，呼叫者会收到一条“[支援] …”聊天提示，写明原因以及冷却是否已返还。

风纪委员的“+2 分钟”没有实现：公示表把格赫娜风纪委员的无人机侦察冷却写成“5+2 分钟”（列为该编制的缺点），但框架每个技能只有一个全局冷却，编制只决定能否使用，代码里也还没有风纪委员编制。现在把 `recon_drone` 加给风纪委员，冷却仍是 5 分钟。以后要做，可以像 F-15EX JDAM 那样注册一个 7 分钟冷却的变体技能 ID 只给风纪委员，或者扩展核心框架支持按编制修正冷却。

已有服务器的 `config/wok_infantry/formations.json` 不会被强制改写；老存档要用新技能，需要管理员把对应 ID 加进编制的 `support.allowList`。千禧年研讨会机动部队应配置为：

```json
"support": {
  "mode": "allow_list",
  "allowList": [
    "wok_commander_support:recon_satellite",
    "wok_commander_support:recon_drone",
    "wok_commander_support:millennium_f15ex_jdam_1000lb",
    "wok_commander_support:f16c_gbu12_paveway_500lb"
  ]
}
```

研讨会骑兵军团为 `recon_satellite`、`recon_drone`、`f16c_gbu12_paveway_500lb` 三项。要给某个编制开放炮击，加入 `wok_commander_support:howitzer_3round_barrage`、`wok_commander_support:howitzer_105mm_rapid_3round_barrage` 或 `wok_commander_support:howitzer_105mm_5round_barrage`。

`mode: all` 会按管理员意图绕过默认专属白名单并允许该编制使用服务器注册的全部支援；要保持千禧年专属，请让其他编制维持 `allow_list` 且不要加入 F-15EX JDAM ID。

## 管理员冷却指令

权限等级 2 的管理员可清除一个阵营、一个稳定支援 ID 的持久冷却：

```text
/battle admin support cooldown clear <blue|red> <支援ID>
```

例如立即恢复蓝方 JDAM：

```text
/battle admin support cooldown clear blue wok_commander_support:millennium_f15ex_jdam_1000lb
```

该指令只清除冷却，不取消正在执行的侦察、炮击或其他在途任务。

从 0.1.0-beta.1 升级时，已经开始的 15 分钟 JDAM / F-16C 冷却按旧到期时间走完（存档里记录的是到期 tick，不随新定义缩短）；需要立即按 10 分钟规则恢复时，用上面的指令清除。存档格式本身不变。

## 构建

先构建同仓库核心，再构建本模块：

```powershell
cd ..\wok_infantry

cd ..\wok_commander_support

```

构建只把核心 JAR 作为开发依赖，不会将其类打进本模块成品。
