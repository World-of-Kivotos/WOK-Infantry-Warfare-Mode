# WOK步战附属-指挥官支援

当前产物 `build/libs/wok_commander_support-0.1.0-beta.2.jar`，最低核心版本为 `0.3.0-beta.5`（依赖核心的失败分级、冷却返还、`requiresLoadedFootprint` 与照射许可内圈接口）。开发构建自动读取核心 `gradle.properties`，不再固定使用旧同名包。

Minecraft 1.20.1 / Forge 47.4.22 独立附属模块，modId 为
`wok_commander_support`，当前版本 `0.1.0-beta.2`。本模块强制依赖
`WOK步战核心`（`wok_infantry`），但不依赖创伤治疗、部位血量、独立护甲、
TaCZ 或任何具体载具 MOD。Create Big Cannons 只作为空袭弹体的可选软依赖，
卓越前线只作为爆炸实现的可选软依赖；缺失时模块和侦察卫星仍可启动，
CBC 缺失会令两种空袭条目明确显示不可用。卓越前线缺失时 F-15EX 安全回退
CBC HE 爆炸，必须使用火炮指示器的 F-16C 宝石路支援则显示不可用。

## 侦察卫星

- 仅当前阵营指挥官能在战术地图的“支援”页呼叫。
- 点选一个扫描中心；服务端校验其所在维度、坐标范围和半径 150 格扫描区的世界边界，不要求扫描区内的区块已经加载（定义声明 `requiresLoadedFootprint=false`），也不会为扫描加载区块。扫描只读取已加载的实体，未加载区域里没有可报告的目标。
- 冷却 10 分钟（以《步战模式公示表》阵营表为准），按阵营和技能 ID `wok_commander_support:recon_satellite` 持久化；更换指挥官或重启服务器不会刷新冷却。
- 呼叫后立即扫描，此后每 5 秒刷新一次，共覆盖 30 秒（6 个刷新窗口）。
- 情报属于阵营：指挥官在侦察期间阵亡（包括停在死亡界面）、进入等待区或换维度，扫描照常刷新到结束。首次扫描就失败（什么都没发布到地图上）时返还冷却；首次扫描之后指挥官下线，本次侦察提前结束，冷却不返还（核心只接受呼叫者当前在线的会话发布情报，重生前的旧实体也不算）；指挥官离开受理阵营时跳过该次扫描，由核心在下一步前取消任务。
- 扫描同维度、圆形水平范围内已部署且存活的敌方玩家；玩家正在乘坐实体时只显示所乘载具的接触点，避免两个红点重叠。
- 同时扫描带有 WOK 编制 ownership 的敌方载具，包括当前无人乘坐的已部署载具。
- 结果仅出现在调用方阵营的战术地图中，统一显示为不可手动选择/删除的红点；目标离开区域后，旧点会在一个刷新间隔后自然消失。
- 红点是运行期临时情报，不占玩家手工标记额度、不写世界存档，服务器重启后不会残留。

## 千禧年 F-15EX 杰达姆 1000磅空袭

- 稳定技能 ID 为 `wok_commander_support:millennium_f15ex_jdam_1000lb`；新生成配置仅向学院军的 `millennium_seminar_mobile`（“千禧年研讨会机动部队”）开放。
- 现任阵营指挥官在战术地图选择一个点即可呼叫；服务端重新校验维度、世界边界、以目标点为中心的 32 格执行区和区块加载状态。
- 冷却 10 分钟（以《步战模式公示表》阵营表为准，0.1.0-beta.1 暂定的 15 分钟已作废），按阵营和技能 ID 持久化；更换指挥官或重启服务器不会刷新冷却。
- 呼叫成功后先进入 200 tick（10 秒）服务端在途倒计时；战术地图显示支援正在接近，倒计时期间不生成航弹实体。
- 第 10 秒生成真实的 Create Big Cannons `createbigcannons:he_shell`，位置精确位于目标正上方 200 格；飞行阶段关闭物理碰撞偏航，不会再擦着地形斜向滑翔。
- 飞行计划按 CBC 线性阻力补偿；20 tick（1 秒）后把同一枚炮弹精确收束到地表并静止，播放沉重触地声，再启动 40 tick（2 秒）延迟引信。
- 呼叫后约第 13 秒优先调用卓越前线 0.8.9 的 `CustomExplosion.Builder`：1000 点爆炸伤害、32 格半径、`GIANT` 爆炸粒子，并沿用卓越前线服务端的方块破坏配置和 Forge 爆炸事件链；调用成功后移除 CBC 弹体，绝不叠加第二次爆炸。
- 卓越前线未安装或运行时接口不兼容时，才把同一枚 CBC HE 炮弹的倒计时归零作为保底爆炸，避免 JDAM 变成哑弹。飞行与爆炸阶段继续叠加 DVIDS 公有领域 F-15E 靶场实录，来源和变换记录见 `THIRD_PARTY_NOTICES.md`。
- 弹体需要 Create Big Cannons `5.11.4` 至 `6.0.0` 之前版本；卓越前线 `0.8.9+` 为可选爆炸后端。两者都只通过注册 ID或反射软联动，不把第三方类打进成品。

## F-16C GBU-12 宝石路 II 500磅精准空袭

- 稳定技能 ID 为 `wok_commander_support:f16c_gbu12_paveway_500lb`；新生成的全部默认编制均开放，冷却 10 分钟（以《步战模式公示表》阵营表为准）。
- 指挥官只在战术终端点选许可区中心；地图点击本身不是激光目标。两个半径：
  - 照射许可区 R64（`F16C_PAVEWAY_GUIDANCE_RADIUS`）：只有落在这个圈内的照射点才算有效照射，释放和每 tick 修正都按它判定。
  - 危险区 R80（`F16C_PAVEWAY_DANGER_RADIUS` = 64 + 爆炸半径 16）：支援定义半径，覆盖最远可能的毁伤边缘。服务端按它校验同维度、世界边界和区块加载，地图按它画红色危险区。
- 战术地图在红色危险区内另画一圈琥珀色虚线内圈，标注“照射许可 R64m”；选点预览、在途和执行中都显示。
- 呼叫后有 10 秒在途时间。释放瞬间，服务端从同阵营在线玩家中选取一名正在主手持续使用卓越前线 `superbwarfare:artillery_indicator` 的制导员；敌方、旁观者、死亡玩家和照射点在许可区外的玩家均不参与。
- 多名友军同时照射时，选取落点最接近许可区中心的一名并锁定其 UUID，后续不会在不同光斑间跳转。制导员可以不是指挥官，也不需要站在许可区内，只要求同阵营、同维度且 512 格服务端射线确实命中许可区。
- 航弹使用真实 CBC `createbigcannons:he_shell`，从斜上方进入并飞行 60 tick（3 秒）。释放点有四个对角候选（光斑周围 (±96, +120, ±96)），先试离制导员最近的一个，取第一个区块已完成加载的；检查候选点不会加载区块。服务器每 tick 重做方块/实体射线，持续照射移动玩家或载具时，航弹会按最新命中点修正弹道。
- 制导员松开使用键、切换物品、离线、死亡、换维度、变更阵营或把照射点移出许可区后，制导立即永久断开；航弹保持最后一次合法修正完成余下飞行，不会自动换人或重新捕获。
- 服务端照射射线不会加载区块：水平射程只到许可区远端再加 16 格（最多 512 格），遇到第一个未加载的区块即停止。“已加载”指区块已经完成加载（`getChunkNow`），挂了票据但仍在读盘或生成的区块也按未加载处理，射线不会让主线程等它。只有真正打到方块或射线前方的实体才算光斑；指向天空、或射线被未加载区块截断，都不算有效照射。
- 最终在最后一个合法光斑触发卓越前线 `CustomExplosion`：500 点伤害、16 格半径和 `LARGE` 粒子。卓越前线爆炸接口临时失败时归零同一枚 CBC HE 的倒计时保底，不生成第二枚航弹。
- 释放时许可区内没有有效友军持续照射：不生成航弹，任务直接结束并返还冷却，呼叫者收到聊天提示“[支援] F-16C GBU-12 宝石路 II 500磅精准空袭 未能投送：许可区内没有友军持续照射，冷却已返还”，可以立刻再次呼叫，不再空转剩余的制导步骤。动作栏另有“宝石路航弹未释放：许可区内没有友军持续照射”，它不说冷却是否返还；以聊天提示为准（管理员在途期间改过冷却时不返还，聊天提示里也不会写“冷却已返还”）。四个释放点区块都未加载时同样不释放并返还，原因为“释放航线区块未加载，需有友军靠近目标外围”。
- 音效：释放时播放 `paveway_f16_approach`（字幕“F-16C 从高空掠过”），命中时播放 `paveway_bomb_tail`（字幕“宝石路航弹爆炸回响”）。两者复用 F-15EX 的同两段 DVIDS 公有领域 F-15E 靶场实录，音调 1.1，不是 F-16C 原声，也没有另外打包音频；来源与变换记录见 `THIRD_PARTY_NOTICES.md`。接近音只在约 181 格外的释放点播放一次，`sounds.json` 为它（以及 F-15EX 的 `jdam_f15_approach`）设置 `attenuation_distance: 96`，按音量 3 可听 288 格，覆盖许可区地面。音效播放失败只记日志，不影响任务。

## 失败处理

规则是“打不出去就返还冷却、立刻能再呼叫”，不另加防刷限制。冷却在受理时扣下；只有在第 0 步（侦察的首次扫描、空袭的释放）还没完成时结束的任务才会返还，第 0 步执行过之后一律不返还。返还由核心按比对写回：管理员中途清除或改过冷却，就保持管理员的结果。任务没有完成就结束时，呼叫者会收到一条“[支援] …”聊天提示，写明原因以及冷却是否已返还。

| 情况 | 结果 | 冷却 |
| --- | --- | --- |
| 在途期间（释放前）核心取消：呼叫者已不在受理阵营、目标维度不可用、覆盖区块卸载或超出世界边界、技能不可用 | 结束本次 | 返还 |
| 释放后核心因同样原因取消 | 撤回已释放的弹体，结束本次 | 不返还 |
| F-16C 释放时许可区内没有友军持续照射 | 结束本次（“许可区内没有友军持续照射”） | 返还 |
| F-16C 四个释放点区块都未加载 | 结束本次（“释放航线区块未加载，需有友军靠近目标外围”） | 返还 |
| JDAM 释放时目标点已超出世界边界 | 结束本次（“目标点已超出世界边界”） | 返还 |
| 空袭释放时弹体未能进入世界 | 结束本次（“弹体未能进入世界”） | 返还 |
| 空袭释放前 Create Big Cannons 炮弹接口不可用 | 该技能停用到服务器重启（“CBC 炮弹接口不可用”） | 返还 |
| 弹体在命中前消失 | 结束本次（“JDAM 炸弹 / 宝石路航弹 已在命中前消失”） | 不返还 |
| 释放后 Create Big Cannons 炮弹接口不可用，或 F-16C 制导出现未预期异常 | 撤回弹体，该技能停用到服务器重启 | 不返还 |
| 侦察首次扫描失败（什么都没发布） | 结束本次；接口损坏或未预期异常时另停用技能 | 返还 |
| 侦察首次扫描之后指挥官下线或发布被拒 | 结束本次 | 不返还 |
| 侦察首次扫描之后出现未预期的运行时异常，或情报批次不合法（数量、持续时间、空目标、超出扫描区或高度） | 侦察卫星停用到服务器重启 | 不返还 |
| 侦察期间指挥官阵亡（包括停在死亡界面）、进入等待区或换维度 | 照常刷新 | 不涉及 |
| 其他未预期的运行时异常 | 该技能停用到服务器重启 | 不返还 |

普通的结束和返还都不会让技能停用；只有接口损坏或未预期的异常才熔断，此后该技能在战术地图上显示不可用，直到服务器重启。释放后 CBC 接口或制导出故障、或核心取消任务时，弹体会先被撤回，不会留在目标上方漂移或成为哑弹。弹体所在区块已经卸载时无法当场撤回，它会随区块存盘；本附属释放的弹体一旦从区块存档读回，就在进入世界时直接丢弃。音效与进度日志失败不影响任务结果。

## 编制权限

新生成的默认编制里，两阵营的 `default`、凯撒 `caesar_234_mechanized` 与学院军
`millennium_seminar_cavalry_corps` 开放侦察卫星与 F-16C 宝石路空袭；学院军
`millennium_seminar_mobile` 另外开放其专属 F-15EX JDAM 空袭。每个技能只有一个全局冷却，
编制只决定能否使用，不能按编制改冷却。已有服务器的
`config/wok_infantry/formations.json` 不会被强制改写；千禧年编制应配置为：

```json
"support": {
  "mode": "allow_list",
  "allowList": [
    "wok_commander_support:recon_satellite",
    "wok_commander_support:millennium_f15ex_jdam_1000lb",
    "wok_commander_support:f16c_gbu12_paveway_500lb"
  ]
}
```

`mode: all` 会按管理员意图绕过默认专属白名单并允许该编制使用服务器注册的全部支援；要保持千禧年专属，请让其他编制维持 `allow_list` 且不要加入 F-15EX JDAM ID。

## 管理员冷却指令

权限等级 2 的管理员可清除一个阵营、一个稳定支援 ID 的持久冷却：

```text
/battle admin support cooldown clear <blue|red> <支援ID>
```

例如立即恢复蓝方 JDAM：

```text
/battle admin support cooldown clear blue wok_commander_support:millennium_f15ex_jdam_1000lb
```

该指令只清除冷却，不取消正在执行的 30 秒侦察或其他在途任务。

从 0.1.0-beta.1 升级时，已经开始的 15 分钟 JDAM / F-16C 冷却按旧到期时间走完（存档里记录的是到期 tick，不随新定义缩短）；需要立即按 10 分钟规则恢复时，用上面的指令清除。存档格式本身不变。

## 构建

先构建同仓库核心，再构建本模块：

```powershell
cd ..\wok_infantry
.\gradlew.bat jar
cd ..\wok_commander_support
..\gradlew.bat build
```

构建只把核心 JAR 作为开发依赖，不会将其类打进本模块成品。
